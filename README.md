# CyberLens - محلل أمني ذكي

مشروع CyberLens هو مشروع تخرج يهدف إلى فحص الروابط، ملفات الكود، ملفات المكتبات، والمشاريع المضغوطة ZIP من ناحية أمنية.

يقوم النظام باكتشاف الملاحظات والثغرات الأمنية، ثم يحسب درجة الأمان، ويعرض شرحًا ذكيًا للنتائج، مع إمكانية إنشاء تقرير PDF.

---

## فكرة المشروع

كثير من الطلاب والمطورين يستخدمون مكتبات أو يكتبون كودًا يحتوي على أخطاء أمنية بدون أن ينتبهوا لها.

لذلك تم بناء CyberLens لمساعدة المستخدم على:

- اكتشاف المشاكل الأمنية.
- فهم سبب الخطورة.
- معرفة درجة أمان المشروع.
- ترتيب المشاكل حسب الأولوية.
- إنشاء تقرير PDF للنتائج.

## أنواع الفحص

### 1. فحص الروابط

يفحص الرابط ويكشف مؤشرات الخطر مثل:

- استخدام HTTP بدل HTTPS.
- وجود IP بدل اسم نطاق.
- وجود IP محلي أو خاص.
- وجود كلمات مشبوهة.
- استخدام منفذ غير شائع.
- وجود Redirect داخل الرابط.

---

### 2. فحص الكود

يفحص ملفات الكود ويكشف مشاكل مثل:

- كلمات مرور مكتوبة داخل الكود.
- استخدام دوال خطيرة.
- تعطيل التحقق من شهادة SSL.
- أنماط برمجية غير آمنة.

---

### 3. فحص المكتبات

يفحص ملفات المكتبات مثل:

- requirements.txt
- package.json
- package-lock.json
- composer.lock
- go.mod
- Cargo.lock

ويتحقق من وجود ثغرات معروفة باستخدام OSV.

---

### 4. فحص مشروع ZIP

يمكن رفع مشروع كامل بصيغة ZIP، ويقوم النظام بفحص:

- ملفات الكود.
- ملفات المكتبات.
- بنية المشروع.

كما يحتوي على حماية أثناء فك الضغط مثل:

- منع Path Traversal.
- تقليل خطر ZIP Bomb.
- منع الروابط الرمزية الخطيرة.
- حذف الملفات المؤقتة بعد الفحص.

## طريقة تشغيل المشروع

### 1. تجهيز البيئة الافتراضية

على ويندوز:

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
```

على لينكس أو ماك:

```bash
python3 -m venv venv
source venv/bin/activate
```

### 2. تثبيت المكتبات

```bash
pip install -r requirements.txt
```

### 3. إعداد ملف البيئة

```bash
cp .env.example .env
```

ثم افتح `.env` واملأ القيم المطلوبة:

- `CYBERLENS_SECRET_KEY` — ولّده بالأمر:
  `python -c "import secrets; print(secrets.token_hex(32))"`
- `CYBERLENS_ADMIN_USERNAME` و `CYBERLENS_ADMIN_PASSWORD` — حساب
  المدير الأول. لا توجد بيانات اعتماد افتراضية في الكود، فإن تركتهما
  فارغين لن يُنشأ أي حساب ولن تستطيع تسجيل الدخول.

### 4. التشغيل

للتطوير المحلي:

```bash
python wsgi.py
```

ثم افتح `http://127.0.0.1:5000`.

للإنتاج:

```bash
gunicorn wsgi:app
```

قاعدة البيانات تُهيّأ تلقائيًا عند الإقلاع في الحالتين.

## ملاحظات أمنية مهمة

- **لا تشغّل المشروع بـ `FLASK_DEBUG=true` على خادم عام.** مصحّح
  Werkzeug يسمح بتنفيذ أوامر عن بُعد لمن يصل إليه.
- `HOST` الافتراضي `127.0.0.1`. لا تغيّره إلى `0.0.0.0` إلا إذا كنت
  تقصد كشف الخادم على الشبكة، ويفضّل حينها وضعه خلف بروكسي عكسي.
- ملف `.env` مستثنى في `.gitignore`. تأكد أنه لم يُرفع أبدًا.
- الفحص الشبكي السلبي يمنع العناوين الداخلية والمحجوزة
  (`127.0.0.1`، الشبكات الخاصة، و`169.254.169.254`) لمنع استخدام
  الأداة للوصول إلى شبكتك الداخلية أو بيانات اعتماد السحابة.
- تحديد معدل محاولات الدخول يعمل في ذاكرة كل عملية. إن شغّلت
  gunicorn بعدة عمّال (`-w 4`) فاستخدم Redis أو `Flask-Limiter`
  للحصول على حد مشترك دقيق.

```
│   ├── app.py                    # تطبيق Flask والمسارات

│   ├── cvss_mapper.py            # ربط النتائج بـ CVSS
│   ├── ai_engine.py              # التحليل الذكي
│   ├── gemini_ai_provider.py     # مزوّد Gemini
│   ├── groq_ai_provider.py       # مزوّد Groq
│   └── pdf_report.py             # توليد تقارير PDF
├── frontend/                     # الواجهة

├── wsgi.py                       # نقطة الدخول
├── Procfile                      # أمر التشغيل للإنتاج
└── requirements.txt
```
